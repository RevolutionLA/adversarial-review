## 蓝军原话（结论段）

> 这个 skill 的**角色设定与流程立意是真的好**，但它的**工程外壳是坏的**，而且坏在最要命的地方：**它以"经过自身三方评审后才定稿"的权威姿态发布，而它自带的校验器、CI、示例文档全都无法发现它自身的问题。** 更严重的是——**本机 `~/.claude/skills/adversarial-review` 里装着的仍然是含缺陷的 v1.0**，而 v1.1.0 声称修复的那个核心缺陷恰好就在那份旧版里原样存在。也就是说：**"已修复"这句话，在发布者的自己机器上就是假的。**

## 关键证据链（摘录）

### B1 · 校验器块标量解析失效

- **代码位置**：`scripts/validate-skill.mjs`（修复前）第 35-74 行 `parseFrontmatter`，致命分支在第 63-68 行。
- **根因**：当 `value === ""` 时设 `currentBlock`，但后续缩进行**只在 `currentBlock === "metadata"` 时被消费**（第 48-54 行），其余块标量的内容被整块丢弃。

**实测输出**：

```
  · description 长度: 2 / 1024 字符
  ⚠ `description` 偏短 (2 字符)，不足以让 agent 判断何时该用它
  ✅ 通过 Agent Skills 规范校验
结果: 全部通过
EXIT=0
```

**蓝军的精确判读**：`compatibility` 折叠块实际 700 字符、直接违反 500 上限，脚本却**恰好报了错**——这是"**巧合对了、理由全错**，比错更危险，因为它给了'校验器有效'的假象"。

**用户可见后果**：作者写了一个 5000 字符、超出规范 5 倍的 description，本地跑校验器看到绿色"✅ 通过"，于是放心提交。发布后宿主端截断或拒绝加载，**skill 静默不触发**——而作者手里握着一张"已通过校验"的证明。

### B2 · SKILL.md 零处引用配套文件

```
Select-String -Path SKILL.md -Pattern 'references/|examples/|scripts/'
→ 0 结果

Select-String -Path SKILL.md -Pattern '\]\('
→ 0 结果（SKILL.md 内没有任何 Markdown 链接）
```

对照：`references/quickstart.md` 说"SKILL.md 末尾有「提示词设计要点」表"——**方向是反的**，整个 `references/` 是单向来引用。

### B3 · 结构不符合 skills.sh 索引要求

skills.sh 官方发布规范要求 `skills/<name>/SKILL.md`；本仓库为根目录 `SKILL.md`。**结论：不会被索引。**

### B7 · "已修复"在发布者本机是假的

实测本机 `~/.claude/skills/adversarial-review/SKILL.md`：

```
行数: 255
含'中立裁定': False
含'蓝军裁定': True      <- v1.0 的缺陷版本
含'降级模式': False
```

## 蓝军做得对、值得保持的（原文摘录）

- 「能力边界」章节主动声明同模型互搏抓不出共同盲区——**这类"主动认怂"的写法极为罕见且极有价值**，改造时不要删。
- 级联的级别定义（🔴/🟠/🟡）给得具体（"向用户广播错误信息"这种可判定标准），而不是"严重/中等/轻微"这种主观词。
- 强制证据链的设计有效——**蓝军本轮能抓到 B4（行号失效）正是因为它必须逐个核实行号**。

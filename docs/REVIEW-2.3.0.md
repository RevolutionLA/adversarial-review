## 五、🟠 逐条展开

### T1 · 🟠 任意反引号内容都算命令

- **证据链**：`check-report.mjs:82`

```js
const INLINE_CMD = /`[^`\n]{3,}`/;
```

  `:126` 处 `if (INLINE_CMD.test(lines[i])) return null;` —— **只要「复现命令」这一行里存在任意一段 ≥3 字符的行内代码，就判证据成立**，完全不校验内容是否像一条命令。

- **复现命令**（实测输出）：

```bash
printf '# 蓝军报告\n\n## 缺陷总表\n\n| 编号 | 级别 | 定级依据 | 一句话 | 维度 | 位置（文件:行号） |\n'\
'|---|---|---|---|---|---|\n| B1 | \xf0\x9f\x94\xb4 | 实测 | 会导致崩溃 | 正确性 | src/a.js:12 |\n\n'\
'### B1 \xc2\xb7 \xf0\x9f\x94\xb4 \xe4\xbc\x9a\xe5\xaf\xbc\xe8\x87\xb4\xe5\xb4\xa9\xe6\xba\x83\n\n'\
'- **\xe5\xa4\x8d\xe7\x8e\xb0\xe5\x91\xbd\xe4\xbb\xa4**\xef\xbc\x9a`\xe8\xa7\x81\xe9\x99\x84\xe5\xbd\x95`\n\n'\
'## \xe9\x99\x84\xe5\xbd\x95\n\n\xef\xbc\x88\xe7\x95\xa5\xef\xbc\x89\n' > /tmp/inlinecmd.md
node skills/adversarial-review/scripts/check-report.mjs /tmp/inlinecmd.md; echo "exit=$?"
```

```text
check-report: /tmp/inlinecmd.md
check-report: 1 条缺陷（第 5 行的总表），1 条声称实测（其中高危 1 条），逐条取证通过（全文有效「复现命令」1 处）
exit=0
```

  报告里**没有任何命令**，「复现命令」后面是三个汉字的行内代码 `` `见附录` ``，机检器放行。

- **触发条件**：蓝军写 `- **复现命令**：\`TODO\`` / `` `见附录` `` / `` `同上` `` 这类占位——这正是模型在不想真跑时最自然的写法。
- **用户可见后果**：这条规则的承诺是「编造的实测会变成可发现的缺陷」。现在往反引号里塞任意 ≥3 字符就能给 🔴 盖章，**代价比 v2.2 那个凑字数的绕过还低**（当时好歹还要在正文里摆个标题）。`check-report.mjs:13` 的注释宣称「把别处的命令挪来共用都不再算证据」，与现实不符。
- **修复方向**：把「有反引号」升级为「反引号里的东西像一条命令」：

```js
// 至少要求：ASCII 开头的可执行片段 + 至少一个参数，或带提示符
const CMDISH = /^\s*(?:[$>]\s+)?(?:[A-Za-z_][\w.-]*|\.\/[\w.-]+)(?:\s+[^\s]+)+/;
const inlineCommandish = (line) =>
  [...line.matchAll(/`([^`\n]+)`/g)].some((m) => CMDISH.test(m[1]));
```
  并补一条红用例（`` 复现命令：`见附录` `` → 必须 `exit 1`）与一条突变（删掉 `CMDISH` 校验 → 该用例必须转红）。

### T2 · 🟠 取证窗口越界，命令可以放在别人的章节里

- **证据链**：`check-report.mjs:127`

```js
if (hasCommandFence(lines, i + 1, Math.min(end + 9, lines.length))) return null;
```

  `end` 是本小节的下一段边界，而窗口又往后伸了 9 行——**伸进了下一个小节或文末附录**。这正是注释宣称已堵死的「把别处的命令挪来共用」。

- **复现命令**（实测输出）：

```text
check-report: /tmp/appendix.md
check-report: 1 条缺陷（第 5 行的总表），1 条声称实测（其中高危 1 条），逐条取证通过（全文有效「复现命令」1 处）

```

  **距离敏感**是它越界的直接证据：我把附录挪远到 9 行之外另做了一份（`borrow-far.md`），那份是红的。也就是说越过 `end` 的那 9 行就是唯一泄漏通道，不是什么设计意图。

- **触发条件**：本小节之后 9 行内存在任意非空围栏块——包括「文末通用脚本」「下一节的例子」这些完全正常的写法。
- **用户可见后果**：同一份「通用脚本」可以喂给全部 N 条高危，等于把「逐条取证」降级回「全文有一处就行」，只是多了 9 行的距离限制。

```js
-if (hasCommandFence(lines, i + 1, Math.min(end + 9, lines.length))) return null;
+if (hasCommandFence(lines, i + 1, end)) return null;
```
  再加一条红用例（小节自己没命令、命令在文末附录 → 必须 `exit 1`）和一条把它改回 `end + 9` 的突变（可编号 P7）。

## 六、🟡 条目

- **T3** `prompt-templates.md:113` —— 模板 2 只说「必须贴出可原样重跑的命令与实际输出」，但机检器要求两个**格式前提**：① 锚点小节必须写成 `### T1 · …`（`check-report.mjs:61-66`）；② 证据行的字面标签必须是「复现命令」（`check-report.mjs:81`）。模板 2 既没给锚点写法，全文件里「复现命令」也只出现在模板 1（第 61 行）与第三方重跑条款（第 94 行）。后果是双向的：写错格式的第三方报告被判红，而模板又要求他们「自跑机检器补到绿」——他们只能猜机器上要的是哪个字。建议在模板 2 的展开要求里补一句：小节标题用 `### <编号> · <级别> <标题>`，命令前加 **复现命令** 标签。
- **T4** `scripts/check-docs.mjs:376-385` —— 「第 N 道门禁」点名校验取 `line.match(/[\w-]+\.mjs/g)` 的全部命中，只要**有一个**落在合法集合（`gate` 或其去掉 `test-` 前缀的形式）里就判通过（只有 `clash.length === named.length` 即全部命中都错时才报错）。README:347 天然同时提到 `check-report.mjs`（被视为 `test-check-report.mjs` 的合法简称）与 `test-check-report.mjs`，因此这句几乎无法被追究。建议改为「只要出现**本轮其他** node 门禁的脚本名就报错」，或把判定粒度收窄到该从句。
- **T5** `README.md:50-63` —— 首屏演示 ① 的输出从 `--- 二、块标量语义 ---` 起，但 `test-validate-skill.mjs:110` 会无条件先打印 `--- 一、块标量解析（字符数断言） ---` 及其下的若干行。也就是说粘贴出来的段落省略了第一节，却没有省略标记。CHANGELOG 明确写了「三段演示输出全部按本版实况重跑后**逐字**替换」——在一个把「逐字引用的工具输出」当资产的项目里，这个口径值得自己守住。建议补一行 `…（略：第一节字符数断言全部通过）`，或把第一节也贴进去。
- **T6** `check-report.mjs:61-66` —— `anchorRe(id)` 把报告里的编号未经转义拼进 `RegExp`。含 `(`, `[`, `+`, `*` 等元字符时行为错乱，不平衡时直接抛未捕获异常。实测（编号 `B(1`）：

```text
SyntaxError: Invalid regular expression: /^(?:\s{0,3}#{1,6}\s+…B(1(?![0-9A-Za-z])/u: Unterminated group
    at new RegExp (<anonymous>)
    at anchorRe (…/check-report.mjs:62:3)
```

  编号写成 `P(1)` 时更隐蔽：`(1)` 变成捕获组，`### P(1)` 反而匹配不上，被误报成「没有展开段落」。修复：`new RegExp(...)` 前做 `id.replace(/[.*+?^${}()|[\]\\]/g, "\\$&")`。

## 七、覆盖度稽核：为什么这两条绕过能活过两套测试

这两条能存在，不只是实现细节，是**关卡本身缺格子**：

| 缺口 | 说明 |
|---|---|
| `test-check-report.mjs` 15 个用例里，没有一条覆盖「标签写了但内容是占位词」 | 用例 13（空围栏）离它最近，但测的是围栏**为空**，不是围栏/行内代码的**内容不像命令** |
| 15 个用例里，没有一条覆盖「命令放在别的章节」 | 用例 12 只证明了「摆个空标题不行」，没证明「命令必须在本小节内」 |
| 18 条突变里，没有一条攻击取证边界或证据内容判定 | P1/P3/P4 分别攻击「有没有取证」「取证范围是 🟡 还是 🔴/🟠」「空围栏算不算」，都绕开了这两处 |
| 于是：**突变测试全绿（17 抓住 / 0 逃逸）与这两条洞共存** | 这不是突变测试失效，而是它的靶子还没列出这两个形状 |

这也解释了为什么用例 12 会给人一种「R1 已经彻底解决」的错觉：**它证明的是 v2.2 那一个具体构造被堵住，而不是那一类问题被堵住**。建议把这两条补成红用例 + 突变——正是本项目自己在 `README.md:349` 写的那句：「一个只会放过合规报告的机检器，和没有机检器一样危险」。

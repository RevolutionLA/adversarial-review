## 三、判据从"验有没有"改成"验像不像"（T1/T2 的同一处根因）

- `commandish()`：剥掉 `$ ` / `> ` 前缀 → 必须纯 ASCII（含中文或 `…` 的直接判为说明文字）→ 拒 `TODO/TBD/FIXME/N/A/（略）/---` → 首 token 须像命令名（`[A-Za-z_.\/~@]` 开头）→ **且**要么带参数，要么含 `| & > < $ ;` 或名字里有 `/ .`。
- 行内代码与围栏块**共用这一个判据**（此前是两套规则，才会出现"围栏要求非空、行内只要求两个反引号"的不一致）。
- 窗口闭合在本小节：`fencePairs()` 先做整文开合配对，块**可以**在窗口内开始、在窗口外结束（评审没提、我们自查的 T7 就是这个），判据只看块内是否真有命令。

**代价说清楚**：这是启发式，不是解释器。`echo 任意字符串` 会被当成命令；`pwd`（裸词）不会被认。我们选择宁可漏认裸词，也不放过占位词——因为占位词是攻击面，裸词是误伤面，而误伤会让人关掉检查。

**T3 的验收方式**（评审方下一轮可以直接照做）：拿模板 2 原文，让一个没参与本项目的 Agent 生成一份含 🔴 实测条目的报告，跑 `check-report.mjs`，应该 `exit 0`；此前它会红，而模板里没有一个字说明原因。

## 六、我们仍然没有解决的事（供下一轮攻击）

- `commandish` 是形状启发式：编一条"长得像命令的假命令"（`node fake.js --evidence`）依然能盖章。**机检器验不了命令是否真跑过**，这一段是本轮修复的能力边界，只能靠第三方重跑（模板 2/3 的既有要求）。
- 输出真实性无锚：报告里"命令 + 输出"整段可以手打。目前没有机制区分"贴来的"与"生成的"。
- 突变靶子仍是人工枚举的形状清单，第五节第 2 条就是它的固有缺口。
- `check-docs.mjs` 依旧没有外部测试套件，只靠文件末尾那段自检；自检语料本身可以被改弱——这是本项目当前最大的一块无保护面。

## 先说结论

v2.2.0 把「未经实测不得定高危」从散文约束变成了机器约束，方向是对的。但**这台机检器目前可以被四个汉字绕过**，而它正是这条约束**唯一**的执行机制。同时新规则只落到了模板 1，**模板 2（第三方）的 T 项总表根本没有「定级依据」列**——按模板生成的第三方报告必然被自家机检器判红。

这与本项目 v2.1.0 自评审抓到的「声称已落实到三个模板、实际只进一个」是**同一类缺陷的第三次复发**。机制没坏，落地又漏了一环。

## 🔴/🟠 逐条展开

### R1 · 🔴 机检器的「实测」计数可被正文中四个汉字绕过

- **证据链**：`check-report.mjs:118-123`

```js
const nRepro = (text.match(/复现命令/g) || []).length;
if (measured.length > nRepro) { /* 报错 */ }
```

  计数对象是**全文出现「复现命令」这四个字的次数**，与条目无关、与是否有真实命令无关。只要正文中出现 N 次这四个字，就能覆盖 N 条声称实测的条目。

- **复现命令**（实测输出）：

```bash
printf '# 蓝军报告\n\n## 复现命令\n\n（待补）\n\n## 缺陷总表\n\n| 编号 | 级别 | 定级依据 | 一句话 | 维度 | 位置（文件:行号） |\n|---|---|---|---|---|---|\n| B1 | 🔴 | 实测 | 会导致崩溃 | 正确性 | src/a.js:12 |\n' > /tmp/bypass2.md
node skills/adversarial-review/scripts/check-report.mjs /tmp/bypass2.md; echo "exit=$?"
```

```text
check-report: /tmp/bypass2.md
check-report: 1 条缺陷，1 条声称实测，定级依据与位置齐全（复现命令 1 处）
exit=0
```

  报告里**一个命令都没有**（「复现命令」只是一个空标题），一条 🔴 声称实测，机检器 **exit 0 判通过**。

- **触发条件**：任何一次蓝军产出，只要文中（含引言、章节标题、表格备注）出现与实测条目数等量的「复现命令」字样。
- **用户可见后果**：这条规则是 v2.2 唯一的执行机制。绕过它，v2.2 的核心承诺（"编造的实测会变成可发现的缺陷"）**不成立**，而用户看到的是"机检器已通过"。这比没有机检器更危险——它把假证据包装成了已验证。
- **修复方向**（三选一，推荐 ①）：
  1. **改为按条目就近匹配**：对每个声称实测的编号 `Bn`，在其后的展开段落中查找 `复现命令` 且紧随一个围栏代码块（```），两者都命中才算成立。
  2. 提高证据门槛：要求「复现命令」后 200 字符内出现围栏代码块。
  3. 最低成本兜底：把计数从"全文出现次数"改为"出现在以 `- **复现命令**` 或 `### ` 开头的行上的次数"，并要求该行后跟围栏块。

### R2 · 🟠 模板 2 的 T 项总表缺「定级依据」列，且"与模板 1 同构"是假声明

- **证据链**：`prompt-templates.md:113` 原文——

> 先给 **T 项总表**（与模板 1 同构：`| 编号 | 级别 | 一句话 | 位置（文件:行号） |`），再对 🔴/🟠 逐条展开

  模板 1 的总表是**六列**（`prompt-templates.md:49`）：`编号 | 级别 | 定级依据 | 一句话 | 维度 | 位置`。模板 2 列出的是**四列**，缺「定级依据」与「维度」。

- **复现命令**（实测输出）：按模板 2 逐字构造一份 T 项总表喂给机检器

```bash
printf '# THIRD-PARTY-REVIEW-2.2.0\n\n## 第二部分：新发现的缺陷\n\n| 编号 | 级别 | 一句话 | 位置（文件:行号） |\n|---|---|---|---|\n| T1 | 🔴 | 整改引入空指针 | src/a.js:12 |\n| T2 | 🟡 | 命名不一致 | src/b.js:3 |\n\n### T1 · 🔴 整改引入空指针\n- **复现命令**：`node -e "require(\x27./src/a\x27)"`\n' > /tmp/t.md
node skills/adversarial-review/scripts/check-report.mjs /tmp/t.md; echo "exit=$?"
```

```text
check-report: /tmp/t.md
  ✗ 缺陷总表缺少「定级依据」列 —— 未经实测不得定高危这条约束无法机检
  ✗ T1：定级为 🔴 但定级依据为"(空)" —— 未经实测不得定高危（推理所得最高 🟡）
check-report: 2 处不符合 v2.2.0「未经实测不得定高危」约束
exit=1
```

- **触发条件**：任何一次标准档/重档评审的第三方环节——只要第三方照模板 2 写 T 项总表。
- **用户可见后果**：v2.2 的高危定级规则在**第三方环节整条失效**。第三方是产出 T 项的角色，它的高危不受"未实测不得定高危"约束，也不可能被机检器检查。而第三方恰恰是流程里**最该被约束**的一方（模板 2 第 5 条还专门要求它去抓别人编造实测）。
- **修复方向**：把 `prompt-templates.md:113` 的 T 项总表改为与模板 1 完全同构的六列，并在模板 2 正文补一句"🔴/🟠 必须贴可原样重跑的命令与输出"；同时在模板 2「落盘要求」里要求跑一次机检器。

### R3 · 🟠 机检器没有接进执行流程，只出现在"常见错误用法"里

  - `SKILL.md:98-105`（第 2 步 第三方）：三个方向是"验证整改 / 找新缺陷 / 稽核覆盖度 + 重跑高危证据"，**没有**"对 T 项总表跑机检器"。

## 做得对、值得保持的（改动时不要误伤）

- **`check-report.mjs` 的三条防"永远绿"自曝**（`check-report.mjs:68-69,114-116`）：找不到总表 / 零数据行 / 零级别 emoji 一律 exit 1；用法错误单独 exit 2 不与检查失败混淆。**提取错位导致的静默通过比报错危险得多**——这个判断是对的。
- **`test-check-report.mjs` 的 2 个绿锚**（`test-check-report.mjs:55-65`）：既断言退出码也断言报错文本，还专门留了 `「未实测」不得被误认为实测` 一条锁住正则写坏。本次 R1 能被发现，正是因为先读了这些用例才去看计数逻辑。
- **`check-links.mjs:56-59` 的"先剔除代码块再提取"**：误报会让人关掉检查，比漏报更糟——这条设计哲学值得保留。
- **`verify-install.sh:124-134` 的"跳过就不许宣称通过"**：找不到校验器就明确输出"不能视为完整验证"并 exit 2。这是本项目修复过的"永远绿的检查"的正确形态。
- **CHANGELOG 里那段"诚实记录"**（`CHANGELOG.md:28-34`）：把并发 agent 导致的"逐字引用变成假引用"完整写下来并留下两条纪律。**这种自我纠错记录是本项目最有说服力的资产，任何时候都不要删。**
